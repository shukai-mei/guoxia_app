# Proposal

## Why

租赁房源登记系统的后端 API 已交付完成（guoxia_center 仓库 change `add-lease-listing-system`，20/20 任务完成、API 契约冻结于其设计文档 D4），但系统没有任何操作界面：房源登记、租客浏览、看房预约三大能力只有接口没有页面，业务无法实际运转。本变更在 guoxia_app 仓库（当前为空目录）从零搭建前端 Web 项目，补齐系统闭环的最后一环。

## What Changes

- 从零初始化 Vue 3 + Vite + Vant 4 前端工程（guoxia_app 为空目录，含构建配置、路由、API 客户端、页面骨架）
- 租客端移动页面（按微信小程序 web-view 嵌入的移动端方向设计）：
  - 房源列表页：展示在租房源摘要（标题、位置、户型、面积、月租金），支持关键词与月租金区间组合筛选，含空态
  - 房源详情页：完整信息展示、周边图/找房指引图浏览、内屋视频播放、媒体临时签名 URL 过期后重新拉取；含预约入口
  - 预约提交：姓名、手机号（11 位大陆手机号校验）、期望看房时间，成功/失败提示
- 管理端页面：
  - 房源列表页：全部房源（含下架标记）、上下架操作
  - 房源录入/编辑页：表单校验、媒体上传（图片 jpg/jpeg/png/webp ≤10MB，视频 mp4 ≤100MB，内屋视频至多 1 个）、上传后签名 URL 预览、提交媒体对象 key；编辑时全量替换媒体列表
  - 预约管理页：预约列表（待处理优先）、确认、拒绝（必填拒绝原因）、重复处理提示
- 统一 API 客户端：封装后端统一响应 `{code, message, data}`、错误码（400/404/409）到中文提示的映射、API base URL 环境配置
- 全局加载态/错误态/空态处理与移动端适配（viewport、安全区、触控友好）

## Impact

- **新代码库**：guoxia_app（当前为空目录）将建立完整的 Vue 3 工程与 npm 依赖（vue、vite、vant、vue-router、axios 等）
- **依赖后端 API**：对接 guoxia_center 已冻结的 D4 契约（`/api/*` 租客端、`/admin/api/*` 管理端，统一响应 `{code, message, data}`）；前端不修改任何后端行为
- **部署拓扑**：生产首选 Nginx 托管前端 dist 并反向代理 `/api`、`/admin/api` 到后端（单域名无 CORS）；开发期用 Vite dev server 代理后端；页面按 web-view 移动端设计，小程序壳（web-view 包装）由用户另行配置，不在本项目交付
- **无后端代码改动**：本变更不触碰 guoxia_center 仓库；契约如需变更需两侧同步走流程
