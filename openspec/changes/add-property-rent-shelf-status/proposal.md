# Proposal

## Why

房源新增出租状态（待租出/已租出）并拆分为「上架/下架 + 待租出/已租出」两个维度后，管理端需要配套的录入默认下架、批量上架、列表筛选与出租状态切换界面；租客端需要对已租出房源做只读展示并屏蔽预约，并在预约提交、门禁开门等动作因房源状态被后端拒绝时以页面弹窗拦截（密码类通知由后端短信完成），避免租客对不可看房源误操作。

## What Changes

- 管理端房源列表新增筛选条件：房源名称（标题/位置）、上架状态（全部/上架/下架）、出租状态（全部/待租出/已租出），筛选可组合
- 管理端房源列表状态标记拆分为两组：上架状态（上架/下架）与出租状态（待租出/已租出），原「在租」标签改为「上架」
- 管理端房源列表新增多选与「批量上架」操作（操作前二次确认，成功后列表即时更新）
- 管理端列表行操作新增「标记已租出 / 改回待租出」（操作前二次确认，「标记已租出」确认框提示未结束的预约将失效并短信通知租客）
- 租客端房源列表展示全部上架房源，已租出房源带「已租出」标记
- 租客端房源列表新增出租状态筛选（全部/待租出/已租出），与既有关键词、租金区间筛选可组合
- 租客端房源详情：已租出房源只读展示（完整信息与媒体可见），屏蔽预约表单与预约入口并提示"该房源已租出，暂不支持预约看房"
- 预约提交被后端拒绝（房源已租出/已下架等）时，以页面弹窗展示提示（替换原有 toast 提示方式）
- 我的预约：新增「已失效」状态展示（含失效原因），失效记录不展示开门按钮与密码区域
- 门禁开门失败且原因为房源已租出/已下架时，以页面弹窗拦截展示提示（替换 toast）
- 管理端预约列表：处理状态新增「已失效」展示，已失效申请不提供确认/拒绝/重发操作入口

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `property-management`: 管理端房源列表筛选、批量上架、状态标签拆分、出租状态切换操作
- `property-browsing`: 租客端列表已租出标记与出租状态筛选、已租出房源详情只读并屏蔽预约入口
- `viewing-appointment`: 预约提交失败弹窗展示、我的预约「已失效」状态展示、管理端预约列表已失效状态与操作入口收口
- `door-access`: 开门失败时房源状态类原因弹窗拦截

## Impact

- **页面**：`AdminPropertyList.vue`（筛选、多选、批量上架、出租状态操作）、`PropertyList.vue`（已租出标记、出租状态筛选）、`PropertyDetail.vue`（已租出只读与弹窗）、`MyAppointments.vue`（已失效展示、开门弹窗）、`AdminAppointmentList.vue`（已失效状态与操作收口）；`PropertyForm.vue` 无状态字段（默认值由后端决定）
- **API 层**：`src/api/index.ts`、`src/api/types.ts`（新增 RentStatus 类型与字段、管理端筛选参数、批量上架与出租状态接口）
- **UI 约定**：首次引入 `van-dropdown-menu` 筛选与列表多选模式；房源状态类业务错误码用 `showDialog` 弹窗替代 `showToast`
- **文案**：在租 → 上架 标签调整，对外展示文案需确认
- **测试**：更新 `src/views/__tests__/` 与 `src/api/__tests__/` 相关用例
